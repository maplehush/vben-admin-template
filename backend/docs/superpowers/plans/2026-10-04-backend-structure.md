# 后端结构与规范改造实施计划

**目标：** 将后端模块与命名规范统一，增加可构建的空系统 API 模块，查询请求使用 DTO、响应用 VO，不改变现有 HTTP 契约。

**依据：** 2026-10-04 用户批准的后端整体改造建议，并明确要求新增空 API 模块及查询 DTO/VO。

**约束：** Java 21、Spring Boot 4、MyBatis-Plus；单体部署；不创建 Git 提交；保留现有 URL、JSON 字段、权限与数据范围行为。

## 任务

- [x] 新增 `admin-system-api` Maven JAR 模块，建立 `start → biz → api → core` 依赖并更新结构文档。
- [x] 为用户、角色、部门、菜单、权限、会话、日志和字典查询抽出 DTO/VO；统一分页为 `PageResult`，更新 Controller、Service、测试引用，不改变 JSON。
- [x] 将跨功能异常处理移至系统级 Web 包，检查用户 Mapper 职责和权限入口，增加路由权限覆盖验证。
- [x] 将公共模块测试归位；编写命名、注释、格式化规范，增加项目级 EditorConfig 和 Maven 格式检查。
- [x] 运行完整 `./mvnw clean package`（包含格式检查与单元测试）；核对 API 响应与权限测试。

## 验收重点

- 空 API 模块参与 reactor 构建，但不产生业务接口或第二个可执行程序。
- 查询参数对象均为 DTO、输出对象均为 VO，旧接口路径、字段名、时间格式不变。
- 普通用户无法绕过服务端权限；新增路由时可发现遗漏的权限配置。
- 格式检查在构建中运行，IDE 与构建使用同一规范。
