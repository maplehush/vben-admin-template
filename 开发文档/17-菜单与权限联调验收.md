## 权限边界验收

1. 为临时普通角色只授予某页面，不授予其按钮。该角色登录后应能看到页面，但看不到相应操作按钮；直接调用该操作接口应返回 403。
2. 再授予对应按钮，其 `authCode` 应出现在 `/auth/codes`，操作接口才允许访问。撤销按钮后，后端下一次请求立即拒绝，前端重新拉取权限后隐藏按钮。
3. 为临时角色单独授予一个无按钮的 API 权限，确认它只出现在接口权限授权中，不生成菜单节点。
4. 停用测试按钮或权限后，确认对应权限码失效；恢复原状态。尝试删除仍被角色引用的菜单或权限时应收到冲突响应。
5. 清理临时角色和账号前先解除授权及账号绑定；保留操作审计记录。

## 独立 MySQL 库的 HTTP 权限测试

`backend/admin-module-system/admin-system-start/src/test/java/com/maplehush/admin/PermissionBoundaryMySqlIT.java` 是按需运行的集成测试。它创建随机名称的 MySQL 测试库，由 Flyway 执行当前全部迁移（现为 V1–V11），插入临时普通角色、部门、用户与会话，通过真实 HTTP 请求验证 `/menu/all`、`/auth/codes`、`GET /system/users`、`POST /system/users` 与两类日志查询，最后关闭应用并删除测试库。测试启动后会核对当前连接的数据库名，避免误写开发库。

在 `backend/` 目录执行（需要本地 MySQL；密码通过环境变量传入）：

```bash
RUN_MYSQL_E2E=true TEST_DB_PASSWORD='<MySQL 密码>' \
  ./mvnw -pl admin-system-start -am test \
  -Dtest=PermissionBoundaryMySqlIT -Dsurefire.failIfNoSpecifiedTests=false
```

可选环境变量：`TEST_DB_USERNAME`（默认 `root`）、`TEST_MYSQL_HOST`（默认 `127.0.0.1`）、`TEST_MYSQL_PORT`（默认 `3306`）。普通 `./mvnw test` 不会执行该按需测试。测试使用应用签发的访问令牌和数据库会话，不经过验证码登录页；因此登录页的验证码错误/过期、中英文切换，以及真实浏览器中的按钮显隐仍待实测。自动 HTTP 测试也不能替代浏览器验收。日志查询已经实现；仍需在真实浏览器中确认普通角色的按钮显隐。

2026-10-01 本地运行结果：按需 MySQL HTTP 测试 1 个通过、0 失败；`./mvnw test package` 通过。测试结束后未残留 `maple_hush_it_%` 数据库，开发库仍为 1 个角色、1 个用户。测试中曾发现 `SELF` 数据范围会拒绝向未授权部门创建用户，因此测试角色使用 `DEPT` 范围，并把新用户放入该部门；这是现有数据范围规则的预期行为。
