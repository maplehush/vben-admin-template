# 前端精简与配置

## 目标与边界

模板只运行 Vben Admin 5 的 `apps/web-antdv-next`，UI 组件库只使用 `antdv-next`。Vben 的 `packages/`、`internal/` 仍提供路由、布局、表单、权限、国际化、样式和构建能力，不能按目录名当成另一套 UI 库删除。

本次按 [Vben 精简指南](https://doc.vben.pro/guide/introduction/thin.html) 清理其他 UI 应用、Nitro Mock、上游文档站，以及主应用内未接入后端的示例路由与登录方式。`playground/` 按开发需要保留为组件和页面源码参考，暂不纳入 pnpm 工作区和模板构建；其中的 Mock 接口不作为正式业务接口。系统管理页面已迁入主应用。

## 当前目录

```text
frontend/
├── apps/web-antdv-next/       # 唯一运行的前端应用
│   ├── src/api/               # 认证、用户信息、系统管理接口
│   ├── src/router/            # 固定路由、后端菜单适配与守卫
│   ├── src/views/system/      # 用户、角色、部门、菜单、接口权限、会话
│   ├── src/views/dashboard/   # 工作台
│   ├── src/views/_core/       # 登录、改密、个人中心、错误页
│   └── .env*                  # 应用环境配置
├── packages/                  # 仍被应用使用的 Vben 共享包
├── playground/                # 保留的上游源码示例，不参与构建
├── internal/                  # 构建、Tailwind、TS、lint 配置
├── scripts/                   # 工具与部署脚本
├── pnpm-workspace.yaml        # 仅将 web-antdv-next 纳入 apps 工作区
└── pnpm-lock.yaml             # 精简后依赖锁文件
```

## 运行与配置

在 `frontend/` 执行 `pnpm install`、`pnpm dev`、`pnpm build:antdv-next`。`pnpm dev` 只启动 `web-antdv-next`，默认端口 5999。开发环境中的 `/api` 由该应用的 Vite 代理转发到本地 Spring Boot `http://localhost:8080`。生产部署应由网关将 `/api` 转发到后端；`VITE_GLOB_API_URL=/api` 保持同源访问。

`.env` 放应用标题、命名空间和本地端口；`.env.development` 放开发代理路径与开发工具开关；`.env.production` 放生产资源与压缩设置。Mock 开关已移除，开发时直接连接后端。生产构建产物在 `apps/web-antdv-next/dist/`；Dockerfile 也从该目录复制静态文件。

后端返回的菜单组件路径必须对应 `src/views/` 下的 Vue 文件，例如 `/system/menu/list`。后端模式不需要再维护一份同名静态菜单；登录、首次改密、个人中心作为固定路由保留。新增页面时，同时更新后端菜单配置与相应权限码。

菜单编辑器从实际打包的 `src/views/` 页面自动生成组件选项，排除 `_core` 与页面内部的 `components/modules`，避免手工维护路径清单。系统表格使用 Vben 操作栏按 `auth` 权限码隐藏按钮，超级管理员限制和受保护数据规则继续由各页面的 `ifShow` 判断；后端仍独立执行鉴权。表格状态值沿用本系统的 `ENABLED/DISABLED`，不复制 playground 的数字状态渲染器。

## 继续二开的约束

- 只在 `web-antdv-next` 增加业务页面和应用专属接口；共享 Vben 包仅在多个页面确实共用时修改。
- 只添加实际使用的依赖。不要重新引入 `ant-design-vue`、`element-plus`、`naive-ui` 或 `tdesign-vue-next` 来实现局部页面。
- 示例页面、演示账号、虚假通知与占位数据不能作为正式业务数据；接入真实接口时再补相应功能。
