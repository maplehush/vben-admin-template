# 菜单权限拆分实施计划

设计依据：[15-菜单与权限拆分架构](15-菜单与权限拆分架构.md)。V4–V5 已执行，后端测试、前端构建与 Flyway 验证已通过；仍需登录后的浏览器操作验收。完成条件是新模型承接现有菜单、权限及角色授权，旧资源接口退出，新前端可实际管理菜单与权限。

1. **迁移与保护**：写 V4，先创建新表、复制原数据和角色授权，转换资源管理入口，追加权限管理入口，最后删除旧表。针对干净库和已执行 V1–V3 的本地库核对记录数、外键和管理权限。运行迁移前备份本地库。
2. **鉴权读取**：将 `/menu/all`、`/auth/codes`、`ManagementPermissionService` 改为新表；按钮码来自菜单授权，API 码来自独立权限授权。用测试覆盖页面与按钮独立授予、停用、超级管理员和会话撤销后的查询。
3. **角色授权**：把原 `resources` 授权改为 `menus` 与 `permissions` 两组事务接口；保留超级管理员保护和启用校验，用测试证明两组互不扩大权限。
4. **管理写入与查询**：实现目录/页面/按钮菜单树及独立 API 权限列表，删除旧资源控制器。验证层级、组件白名单、`authCode` 与 API 权限码全局唯一、引用阻止删除和审计。
5. **前端与契约**：菜单页借鉴 playground 的 Vxe 树表和抽屉，权限页独立列表；角色授权拆分；更新语言包、组件白名单、单一 Apifox OpenAPI 和文档。
6. **最终验证**：后端测试/打包、前端类型检查/构建、Flyway 本地迁移、运行实例的 OpenAPI/菜单/权限接口检查。涉及登录的交互由实际浏览器会话补充验证。
