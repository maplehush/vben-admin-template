# 默认数据与初始化

## 迁移顺序

1. `V1__init.sql`：只创建表、约束与索引。
2. `V2__seed_system.sql`：预置 `super_admin` 角色、模板必需菜单、按钮/API 权限资源及角色授权。
3. `V3__session_management.sql`：增加在线会话页面、查询与强制下线权限。
4. `V4__split_menu_permission.sql`：拆分菜单按钮与独立接口权限，保留原 ID 和授权。
5. `V5__rename_menu_query_permissions.sql`：修正 V4 遗漏的菜单查询/详情权限码。
6. 初始化命令：首次创建超级管理员账号并绑定 `super_admin`；不放在 SQL 迁移中。

[`schema/`](../backend/schema/) 是唯一 SQL 维护源，构建时复制到启动 JAR 的 `db/migration/`。V1 至 V5 已在本机 MySQL 8.4.6 中通过 Flyway 执行；首次管理员初始化命令也已实现并在本机执行。迁移提交并执行后不得修改已执行版本；数据变化使用新迁移。

## 预置内容

只预置一个角色：`super_admin`，数据范围 `ALL`。V2/V3 共 34 条旧资源和 34 条授权；V4 迁移后，本机为 29 条菜单/按钮、11 条独立接口权限，以及对应的 29 条、11 条角色授权。应用层仍须将 `super_admin` 视为拥有全部当前及未来资源的保留角色，不可仅依赖静态关系。它只由首次初始化流程绑定到系统账号，不通过用户管理接口授予员工；系统账号的角色也不可在用户管理页替换。没有默认部门、默认用户、测试账号或行业业务菜单。`super_admin` 使用 `role_code` 定位，不依赖数据库自增 ID。

登录页不展示 `Super/Admin/User` 演示账号选择器或预填密码；系统不提供公开注册入口或注册 API。正式账号由首次初始化命令和具有相应权限的管理员创建。

### 权限码

| 页面 | `API`：页面查询，无独立按钮 | `BUTTON`：界面操作及对应后端接口 |
|---|---|---|
| 用户 | `system:user:list`、`system:user:view` | `system:user:create`、`system:user:update`、`system:user:status`、`system:user:grant`、`system:user:reset-password` |
| 角色 | `system:role:list`、`system:role:view` | `system:role:create`、`system:role:update`、`system:role:delete`、`system:role:grant`、`system:role:data-scope` |
| 部门 | `system:dept:list`、`system:dept:view` | `system:dept:create`、`system:dept:update`、`system:dept:delete` |
| 菜单 | `system:menu:list`、`system:menu:view` | `system:menu:create`、`system:menu:update`、`system:menu:delete` |
| 接口权限 | `system:permission:list`、`system:permission:view` | `system:permission:create`、`system:permission:update`、`system:permission:delete` |
| 在线会话 | `system:session:list` | `system:session:revoke` |

同一权限码只在按钮或独立接口权限中登记一次。`system:role:grant` 的 GET 与 PUT 复用一个码；页面自带的列表/详情请求归 `API`，操作按钮归 `BUTTON`。个人资料和修改本人密码只检查登录身份与本人范围，不加入 `system:*` 权限码。控制台目前没有业务统计 API，不预置虚构的 `dashboard:summary` 权限。

## 首次管理员账号

初始化命令仅在 `sys_user` 为空时执行。管理员用户名由部署方通过命令参数输入，初始密码固定为 `12345678`，与新增普通用户的初始密码一致。服务端使用 Spring Security 的 PBKDF2 自适应密码编码器哈希后入库，并设置 `must_change_password=1`；Flyway SQL 不预置管理员账号或密码。命令通过锁定预置角色行和数据库事务防止重复执行覆盖密码或创建第二个初始管理员；导入包含用户数据的数据库时，已有密码保持原值。具体命令见[后端运行说明](../backend/README.md#首次管理员初始化)。首次登录须调用 `PUT /user/password` 修改本人密码；服务端撤销全部旧会话并要求重新登录。

## 幂等与校验

预置菜单和权限以稳定 `menu_key`、`permission_key` 标识，权限码与路由名保持唯一。迁移执行后至少验证：1 个角色、29 条菜单/按钮、11 条独立接口权限及对应授权；31 个权限码与[唯一 OpenAPI 文件](openapi/核心接口.openapi.json)的 `x-permission-code` 对齐；菜单树无环；`super_admin` 能取得菜单和权限码；非超级管理员默认不获得这些授权。还需验证全部组件路径和国际化键可解析。
