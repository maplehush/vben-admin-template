# 代码注释规范

本模板以清晰的命名、短函数、类型和测试表达普通逻辑。注释重点说明**为什么这样做**、业务边界和外部契约，不逐行翻译代码。

## 应当加注释

1. **安全与权限边界**：例如首次改密时为什么不能读取菜单、登录 401 为什么不能触发刷新、前端按钮权限为什么还需要后端校验。
2. **业务规则与例外**：例如超级管理员固有全权、撤销全部会话、父菜单补齐不代表拥有其下所有页面。
3. **跨端契约和兼容处理**：例如 `/api` 代理去前缀、Refresh Token Cookie 的公开 Path、刷新接口为何返回纯文本。
4. **不直观的限制和临时约束**：例如菜单只返回已打包组件；约束解除时应同步删改注释。
5. **复杂算法或并发控制**：说明输入、关键不变量和失败行为，例如刷新令牌在事务内轮换。
6. **公开扩展点**：为其他业务模块调用的接口说明用途、参数约束和返回语义。

## 通常不用加注释

- 字段名、DTO 映射、简单 CRUD、显而易见的条件判断和单行调用。
- 重复方法名或类型名的 Javadoc，例如“获取用户信息”方法再写“获取用户信息”。
- 已由测试名称清楚表达的正常路径。
- 大段被注释掉的旧代码；应删除并交给版本管理。

## 写法与维护

- 注释贴近相关代码，使用简短中文或与所在文件一致的语言；术语和接口路径保持准确。
- 先说明原因和边界，必要时链接同目录的设计文档；不要把会频繁变化的实现细节复制成第二份。
- 修改行为时同步更新或删除旧注释；过期注释比没有注释更危险。
- 不在注释、日志、示例中写密码、令牌、验证码答案等敏感值。
