# Vben `web-antdv-next` 页面移植映射

前端主应用采用 `frontend/apps/web-antdv-next`。`frontend/playground` 使用同一套 `antdv-next` 组件库，并已有用户、角色、部门、菜单页面。Vben 的 `Page`、`Form`、`Modal`、`Drawer`、`Vxe Table` 等封装可复用；移植工作重点是数据契约、权限与路由，不重写通用组件。

## 页面来源与目标

| playground 来源 | 主应用目标 | 对接重点 |
|---|---|---|
| `src/views/system/user/` | `apps/web-antdv-next/src/views/system/user/` | 用户分页、角色分配、状态与详情 |
| `src/views/system/role/` | `apps/web-antdv-next/src/views/system/role/` | 角色分页、菜单与接口权限授权、数据范围 |
| `src/views/system/dept/` | `apps/web-antdv-next/src/views/system/dept/` | 部门树、移动和启停限制 |
| `src/views/system/menu/` | `apps/web-antdv-next/src/views/system/menu/` | 目录、页面、按钮与 `authCode`；独立 API 权限另在 `system/permission/` |

上表记录已完成的页面移植来源；`playground/` 保留为 Vben 页面源码参考，不纳入模板的运行和构建工作区。`playground/src/api/system/` 是 Mock 契约示例，不能原样作为模板 API。模板唯一接口依据是 [OpenAPI 文件](openapi/核心接口.openapi.json)；前端页面移植时以其路径、字段和响应为准。

## 登录页收敛与验证码

正式登录页保留可配置的标题、副标题、账号、密码、图片验证码、记住账号和登录按钮。**用户只需输入账号、密码、图片验证码三项，不保留任何滑块交互。**验证码输入框与图片同行等高，点击图片可刷新；不展示“看不清”和“忘记密码”文字。“记住账号”只是可选勾选项，不属于登录凭据。原版 `web-antdv-next` 的 `Super/Admin/User` 演示账号选择器、自动填入的 `123456` 密码和前端滑块已移除，改为 `GET /auth/captcha` 获取图片；程序把返回的 `captchaId` 作为不可见技术字段随三个用户输入项一起提交。验证码错误或密码错误后重新获取图片；服务端独立限流并原子消费验证码。

通过 Vben 登录组件的显示属性隐藏“创建账号”、手机号登录、扫码登录、第三方登录和“忘记密码”入口，同时不对外开放这些空页面和注册 API。正式找回流程需另行设计。记住账号只在**登录成功后**保存用户名，不保存密码或令牌；共用组件为本应用增加延迟保存选项，并使用独立存储键，避免读取旧演示账号。标题和副标题使用模板品牌文案。

`web-antdv-next` 现已覆盖 Vben 默认配置，设置 `accessMode: 'backend'` 和 `enableRefreshToken: true`。后端模式下普通动态页面来自 `/menu/all`。固定的首次改密页与个人中心位于核心路由中；路由守卫对这两个页面单独核验登录状态，首次改密页还核验 `mustChangePassword`。登录后先取 `/user/info`；需要改密时不并行取 `/auth/codes`，改密完成并重新登录后再加载权限码与菜单。

## 必须修改的差异

1. **路径**：playground 使用 `/system/user/list`、`/system/menu/list` 等单数路径；模板使用 `/system/users`、`/system/menus/tree` 等资源路径。
2. **分页**：用户和角色列表使用 `page,pageSize`，后端返回 `{items,total}`。Vxe Grid 的查询适配器需把该结构交给表格，不再假设返回裸数组。部门和菜单是树，不分页。
3. **字段**：playground 用户示例有 `name`、`permissions`、数字状态；模板使用 `username`、`realName`、`roleIds`、`ENABLED/DISABLED`。角色、部门、菜单和接口权限字段也按 OpenAPI DTO 映射。不要直接把 Mock 类型或数据库实体拷进主应用。
4. **权限**：按钮显示使用 `/auth/codes` 返回的 `system:*` 权限码；后端仍独立鉴权。用户不提供删除按钮，使用停用接口；角色、部门、菜单和接口权限删除受引用与保护规则约束。
5. **菜单编辑**：沿用 playground 的目录、页面、按钮、内嵌、外链及 `authCode` 设计；内嵌和外链地址分别写入 `routeMeta.iframeSrc`、`routeMeta.link`。新增时为两者自动生成内部路由名，并为外链自动生成内部路由路径；编辑时保留已有路由标识。徽标、激活图标、标签页缓存与菜单显示开关按 playground 的路由元数据配置，并由后端 `/menu/all` 返回。没有按钮的 API 权限单独管理。
6. **路由**：种子数据的目标组件为 `/system/user/list`、`/system/role/list`、`/system/dept/list`、`/system/menu/list`。当前已开启 `accessMode: 'backend'`，工作台与系统页面均由后端菜单提供；前端不再保留重复的静态 dashboard 路由。
7. **首次改密**：`/user/info.mustChangePassword=true` 时进入固定的已登录改密页；前端不提前请求 `/auth/codes` 或 `/menu/all`，后端同时限制业务接口。
8. **国际化**：补齐 V2 中 `system.*.title` 菜单键，以及移植页面使用的表格、表单和操作文案。
9. **页面交互**：菜单列表沿用 playground 的树形表格布局，显示标题图标、类型标签、权限标识和路由地址；展示当前后端契约支持的五种菜单类型。用户、角色、部门、菜单和接口权限的新增、编辑统一使用 `useVbenDrawer` 与 `useVbenForm`，表单组件位于各自的 `modules/form.vue`。角色授权、密码重置使用 `useVbenModal`；删除和状态切换等一次性确认使用组件库的确认框。
10. **配置归位**：表单字段 schema、搜索字段 schema、表格列与静态选项放在各页面的 `data.ts`；依赖编辑状态或后端树数据的字段通过配置函数传参。`list.vue` 只保留列表查询和操作入口，`modules/form.vue` 负责表单回填、校验、提交和抽屉状态。示例页的 Mock 字段不能直接复制到本系统。

系统管理的用户、角色、菜单、部门四个二级菜单沿用 `playground` 图标：`mdi:user`、`mdi:account-group`、`mdi:menu`、`charm:organisation`。图标由 `sys_menu.icon` 提供，侧边栏与菜单管理表共用同一数据源；既有数据库由 V6 迁移更新原始种子图标。

## 验收顺序

1. `web-antdv-next` 应用能启动；四个目标页面组件能被动态路由解析。
2. 登录页无演示账号和公开注册；服务端验证码成功、失败、过期、复用与刷新图片场景通过联调。
3. 管理员登录后菜单与权限码一致；无权限用户看不到按钮，直接请求 API 仍收到 403。
4. 用户/角色/接口权限分页、部门/菜单树展示真实接口契约；创建、编辑、状态、授权和删除行为符合后端规则。
5. 刷新令牌、首次改密、停用用户与权限变更后重新拉取菜单的流程通过联调。

当前已完成正式登录页、服务端验证码、首次改密页、后端菜单模式和本地代理的接入。用户、角色、部门、菜单、接口权限和在线会话管理页面已按真实接口实现；后端仅将实际已打包的工作台与六个系统管理页面加入菜单清单。

菜单页已在本地浏览器以超级管理员账号核对“新增菜单”、行内“新增下级/编辑/更多→删除”、新增下级的父菜单预填和编辑回填。菜单的创建、修改、删除及普通角色越权拒绝已在独立 H2 数据库中测试，不在开发 MySQL 库留下测试数据。角色菜单授权变化后，后端 `/auth/codes` 与 `/menu/all` 按当前授权即时计算；前端在登录或重新加载应用、生成动态路由时重新获取权限码和菜单。因此其他已登录浏览器中的按钮和菜单需要刷新页面才会同步，后端鉴权不依赖该前端缓存。普通角色的浏览器实测仍需具备对应测试账号后进行。
