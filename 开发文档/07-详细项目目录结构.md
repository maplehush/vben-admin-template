# 后端详细目录结构

以 2026-10-04 的实际后端工程为准。后端是模块化单体：一个可执行 JAR、一个进程。`biz` 是 business（业务实现）的缩写，沿用 JeecgBoot 对系统实现模块的命名方式；它不表示 DDD 分层。业务服务统一使用接口和实现类。

```text
vben-admin-template/
├── README.md                                # 项目入口
├── frontend/                                # Vben 前端
├── backend/
│   ├── pom.xml                              # Maven 根聚合、依赖版本
│   ├── .editorconfig                        # 编辑器基础格式
│   ├── AGENTS.md                            # 后端开发约定
│   ├── README.md                            # 构建、启动及接口说明
│   ├── mvnw  .mvn/                          # Maven Wrapper
│   ├── schema/

│   │   ├── V2__seed_system.sql              # 基础数据
│   │   └── V3__*.sql ... V12__*.sql         # 后续 Flyway 迁移

│       ├── pom.xml
│       ├── admin-system-api/                # 预留跨模块契约，目前无 Java 类型
│       │   └── pom.xml
│       ├── admin-system-biz/
```

根 POM 聚合 `admin-base-core` 和 `admin-module-system`；系统聚合 POM 包含 `admin-system-api`、`admin-system-biz` 和 `admin-system-start`。依赖方向是 `start → biz → api → core`。API 模块按照项目约定预留为空模块，后续只放真实跨模块契约；没有 Demo 业务模块。

`controller` 负责 HTTP 参数与响应，依赖 `service/ISysXxxService.java`；`service/impl/SysXxxServiceImpl.java` 负责权限、事务和业务规则；`SysXxxMapper` 与 `SysXxx` 实体负责持久化。复杂查询保留独立 `ISysXxxQueryService`，条件使用 `XxxQueryDTO`，返回 `XxxVO` 或 `PageResult<XxxVO>`。单表查询映射实体，联表列表可以直接映射响应 VO，内部鉴权结果确有需要时使用独立类型；实体不直接作为 HTTP 响应。单表筛选、计数和树节点读取使用 MyBatis-Plus `BaseMapper` 与 `LambdaQueryWrapper`；联表、授权范围、行锁和原子条件更新写在 `src/main/resources/mapper/system/` 的 XML。Flyway 只从 `backend/schema/` 维护，构建时复制进启动 JAR。已执行版本不改写。
