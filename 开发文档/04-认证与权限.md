# 认证与权限

## 认证流程

1. 登录页调用 `GET /auth/captcha` 获取一次性图片验证码；服务端将答案短时存入 Redis，前端只接收图片和挑战 ID。
2. `POST /auth/login` 提交账号、密码、挑战 ID 和验证码。服务端原子消费验证码，独立按账号及 IP 限流，再校验账号状态和密码。验证码不能只在前端校验。
3. 创建服务端会话，返回短期 Access Token，并设置 `HttpOnly`、`Secure` Refresh Token Cookie。
4. 前端先读取 `/user/info`；如须首次改密，进入受保护的改密页，完成前不加载权限码和菜单。正常用户再读取 `/auth/codes` 和 `/menu/all`。
5. 前端通过 Bearer Token 访问 API。Access Token 过期时使用 Cookie 调用 `/auth/refresh`；刷新时轮换 Refresh Token，旧令牌立即失效。退出登录或管理员强制下线时撤销会话。每次受保护请求根据 JWT 的 `sid` 查询 MySQL 会话、用户状态和有效授权；第一版不缓存权限决策。

密码只保存自适应哈希；刷新令牌只保存不可逆摘要。跨站部署时需要统一约定 Cookie 的 `SameSite`、域名与 CORS；生产环境必须使用 HTTPS。

模板不提供公开注册，也不预置演示账号。登录页的“记住账号”只在登录成功后保存用户名，不保存密码或令牌；找回流程落地前不展示“忘记密码”入口。图片验证码只是防自动化的一层，仍须保留登录限流和审计。

## 功能权限

用户可绑定多个启用角色，功能权限取并集。遵循 Vben Admin 的菜单设计，`sys_menu` 包含 `CATALOG` 目录、`MENU` 页面、`BUTTON` 按钮、`EMBEDDED` 内嵌和 `LINK` 外链；按钮的 `auth_code` 对应前端按钮显示与后端接口校验。没有对应按钮的接口操作放在独立的 `sys_permission` 表，使用 `permission_code`。`sys_role_menu` 和 `sys_role_permission` 分别存储两类授权。

权限码格式为 `模块:对象:动作`，例如 `system:user:create`。一个权限码只定义一次；“新增用户”按钮和新增用户接口共用 `system:user:create`，不再创建同码 API 权限。`/auth/codes` 合并授权按钮码与独立接口权限码；`/menu/all` 返回目录/页面/内嵌/外链路由树，不包含按钮或接口权限。

`super_admin` 为唯一预置角色，在应用层拥有全部功能和数据权限；不能删除或停用。禁用用户、角色、菜单或接口权限后，其授权对下一次受保护请求生效。第一版不缓存权限决策，也不把权限清单写入 JWT 作为授权依据。JWT 仅标识用户和会话；服务端以 MySQL 当前状态判断是否可访问。

### 授权写入边界

第一版仅当前有效的 `super_admin` 用户可调用用户角色替换、角色菜单与接口权限授权、角色数据范围设置和菜单与接口权限写入接口；功能权限码检查之外还必须检查该身份。`super_admin` 只由首次初始化流程绑定到系统账号，创建用户和角色替换接口均不得授予它，也不得替换系统账号的角色。创建用户请求中的普通 `roleIds` 只有系统超级管理员可提交非空集合，普通管理员创建用户时必须传空集合。普通管理员可在其管理范围内使用获授的用户资料和状态管理权限，但不得管理拥有 `super_admin` 角色的用户。若未来需要委派授权，应单独设计可授予角色的边界与防越权校验，不通过放宽本规则实现。

## 数据权限

`sys_role.data_scope_type` 允许 `ALL`、`DEPT_AND_CHILDREN`、`DEPT`、`SELF`、`CUSTOM`。`CUSTOM` 的部门集合存于 `sys_role_dept_scope`。一次受保护操作先找出**授予该操作权限码**的有效角色，再合并这些角色的数据范围；`ALL` 只覆盖这个集合中的其他范围。没有角色授予该操作时直接拒绝。`super_admin` 是显式例外。不能先合并用户所有角色的数据范围、再独立检查功能权限，否则无该操作权限的宽范围角色也会扩大可见数据。

数据范围作用于业务查询，不自动套用全部表。每个需要数据权限的业务模块须声明记录的 `owner_user_id` 或 `dept_id` 等归属字段，并为列表、详情、更新、删除分别检查范围。禁止仅通过前端筛选或通用字符串拼接 SQL 实现数据隔离。

## 菜单与授权一致性

角色被授予页面时，应一并能看到必要的父级目录或页面菜单；补齐父级不代表获得该父页面及其其他子页面的访问权。未获显式授权的父页面只作为路由容器返回，不下发其页面组件。前端页面组件路径由已注册视图清单校验。角色权限修改后，用户应在下一次权限拉取或刷新页面时看到新菜单；后端接口权限读取 MySQL 已提交的当前授权。
