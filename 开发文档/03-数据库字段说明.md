# 数据库字段说明

本文对应 [`V1__init.sql`](../backend/schema/V1__init.sql) 至 [`V7__add_dept_remark.sql`](../backend/schema/V7__add_dept_remark.sql)。字段类型、可空性、默认值、索引和外键以 SQL 为准。主键与外键统一使用有符号 `BIGINT`，便于映射为 Java `Long`。API 对 JavaScript 客户端传递大整数时应序列化为字符串，避免超过安全整数范围。

时间字段统一采用 `*_time` 风格，例如 `create_time`、`update_time`、`expire_time`；不使用 `*_at`。V11 之后业务列为秒精度 `DATETIME`。MySQL `DATETIME` 不保存时区；连接会话固定为 `+08:00`，应用按北京时间读写。迁移中的 `CURRENT_TIMESTAMP` 默认值须在真实 MySQL 环境验证为北京时间。

时间处理集中在后端 `admin-base-core` 的 `DateUtils`：写入时取得北京时间的 `LocalDateTime`，读取 `DATETIME` 时直接按数据库原值格式化为 `yyyy-MM-dd HH:mm:ss`，不额外加减时差；接收时间范围参数时将带时区的 ISO 8601 时间转为北京时间。`application.yml` 将数据库连接和 Flyway 会话设为 `+08:00`，Jackson 响应时区设为 `GMT+8`。Jackson 配置只负责 JSON 序列化，不能替代 JDBC `DATETIME` 的时区约定；业务服务不要各自添加时间格式化逻辑。

## 通用约定

| 字段 | 含义 |
|---|---|
| `id` | 表主键；关系表可使用联合主键 |
| `create_time` | 创建时间，应用按北京时间读写 |
| `update_time` | 最后更新时间 |
| `status` | `1` 启用、`0` 停用；不等于逻辑删除 |

第一版不做通用逻辑删除。用户、角色、菜单与接口权限需要保留历史时优先停用；执行物理删除前检查关联与审计需求。`email` 的唯一约束允许多个空值。

## `sys_dept` 部门

| 字段 | 含义 |
|---|---|
| `id` | 部门 ID |
| `parent_id` | 上级部门 ID；根部门为空 |
| `dept_code` | 全局唯一且稳定的部门编码；新部门由后端按配置前缀和 ID 生成，例如 `DEPT_0001`，管理表单不手填；历史编码保持不变 |
| `dept_name` | 部门名称 |
| `sort_order` | 同级排序，升序 |
| `status` | 启停状态 |
| `remark` | 可选备注，最多 500 字符 |
| `create_time`、`update_time` | 创建与更新时间 |

不能把部门移动到自己的下级节点；仅已禁用且没有子部门、用户归属或角色数据范围引用的部门可以删除。

## `sys_user` 用户

| 字段 | 含义 |
|---|---|
| `id` | 用户 ID |
| `username` | 唯一登录名 |
| `password_hash` | 自适应密码哈希，绝不存明文 |
| `real_name` | 显示姓名 |
| `email`、`phone` | 可选联系方式 |
| `avatar_url` | 可选头像位置 |
| `primary_dept_id` | 主部门，用于默认数据归属 |
| `home_path` | 登录后首页路由 |
| `status` | 启停状态；停用用户不得登录或刷新会话 |
| `must_change_password` | `1` 表示下次登录必须修改密码；初始密码与重置密码时设置 |
| `password_change_time` | 最近修改密码时间 |
| `last_login_time` | 最近成功登录时间 |
| `create_time`、`update_time` | 创建与更新时间 |

第一版一个用户只有一个主部门。若以后需要一人多部门，再增加关系表并重新定义数据权限语义。

## `sys_role` 角色

| 字段 | 含义 |
|---|---|
| `id` | 角色 ID |
| `role_code` | 唯一角色编码；`super_admin` 是保留值 |
| `role_name` | 显示名称 |
| `data_scope_type` | `ALL`、`DEPT_AND_CHILDREN`、`DEPT`、`SELF`、`CUSTOM` |
| `status` | 启停状态 |
| `description` | 角色说明 |
| `create_time`、`update_time` | 创建与更新时间 |

## `sys_user_role` 用户角色关系

| 字段 | 含义 |
|---|---|
| `user_id` | 用户 ID |
| `role_id` | 角色 ID |
| `create_time` | 绑定时间 |

`(user_id, role_id)` 是联合主键；一个用户可有多个角色。

## `sys_menu` 菜单与按钮

| 字段 | 含义 |
|---|---|
| `id`、`parent_id` | 菜单 ID 与上级菜单 ID；根目录的上级为空 |
| `menu_type` | `CATALOG` 目录、`MENU` 页面、`BUTTON` 按钮、`EMBEDDED` 内嵌、`LINK` 外链 |
| `menu_key` | 唯一且稳定的菜单标识 |
| `route_name`、`route_path` | 目录/页面/内嵌/外链的 Vben 路由名称与路径 |
| `component`、`redirect_path` | 页面组件与目录跳转路径 |
| `auth_code` | 按钮权限码，目录和页面为空；与后端对应接口使用同一码 |
| `title_key`、`icon`、`sort_order`、`route_meta` | 标题、图标、顺序；`route_meta` 存徽标、激活图标、缓存/固定标签及菜单/面包屑/标签栏显示开关 |
| `status`、`create_time`、`update_time` | 启停与审计时间 |

`/menu/all` 返回目录、页面、内嵌和外链；内嵌和外链地址分别保存在 `route_meta.iframeSrc` 与 `route_meta.link`，均须为 HTTP/HTTPS URL。菜单管理树显示按钮节点，但按钮不生成路由。移动菜单须校验父类型、启用状态与无环。

## `sys_permission` 独立接口权限

| 字段 | 含义 |
|---|---|
| `id` | 权限 ID |
| `menu_id` | 可选所属目录/页面，仅用于分组 |
| `permission_key` | 唯一的稳定标识 |
| `permission_code` | 唯一接口权限码，且不能与菜单按钮的 `auth_code` 重复 |
| `title_key`、`icon`、`sort_order`、`route_meta` | 显示信息 |
| `status`、`create_time`、`update_time` | 启停与审计时间 |

只登记没有对应界面按钮的接口操作。权限码由后端代码绑定接口；数据库数据本身不能给任意 URL 增加权限规则。

## 角色菜单与接口权限授权

| 表 | 联合主键 | 含义 |
|---|---|---|
| `sys_role_menu` | `(role_id, menu_id)` | 授予目录、页面或按钮 |
| `sys_role_permission` | `(role_id, permission_id)` | 授予独立接口权限 |

页面授权不自动授予其按钮。为显示路由可补齐父目录，但不扩大角色的显式授权。

## `sys_role_dept_scope` 自定义部门数据范围

| 字段 | 含义 |
|---|---|
| `role_id` | `data_scope_type = CUSTOM` 的角色 |
| `dept_id` | 被包含的部门 |

`(role_id, dept_id)` 是联合主键。仅对 `CUSTOM` 生效，其他数据范围不读取此表。

## `sys_session` 登录会话

| 字段 | 含义 |
|---|---|
| `id` | 会话 ID |
| `user_id` | 所属用户 |
| `refresh_token_hash` | 刷新令牌的不可逆摘要，唯一 |
| `device_info` | 设备摘要或展示信息 |
| `ip_address` | 最近关联 IP，兼容 IPv4/IPv6 |
| `expire_time` | 过期时间 |
| `revoke_time` | 撤销时间；空值表示未主动撤销 |
| `create_time` | 创建时间 |

刷新令牌轮换时应更新或替换会话记录，并确保旧摘要不可再用。

## `sys_login_log` 登录日志

| 字段 | 含义 |
|---|---|
| `id` | 日志 ID |
| `user_id` | 匹配到的用户；未知用户名时为空 |
| `username` | 当次提交的用户名 |
| `success` | `1` 成功、`0` 失败 |
| `failure_reason` | 失败原因编码或简短描述 |
| `ip_address`、`user_agent` | 请求来源信息 |
| `occur_time` | 发生时间 |

## `sys_operation_log` 操作审计

| 字段 | 含义 |
|---|---|
| `id` | 日志 ID |
| `actor_user_id` | 操作者；用户已删除时可为空 |
| `action_code` | 操作码，通常对应权限码 |
| `target_type`、`target_id` | 被操作对象类型与标识 |
| `request_id` | 请求链路标识 |
| `success` | `1` 成功、`0` 失败 |
| `ip_address` | 请求来源 IP |
| `occur_time` | 发生时间 |

日志不存密码、令牌或完整敏感请求体。保留期限和归档策略由使用模板的项目确定。
