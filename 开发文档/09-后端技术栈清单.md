# 后端技术栈清单

本文记录第一版后端选型。工程骨架已锁定 Java 21、Spring Boot 4.1.1、MyBatis-Plus 3.5.17、springdoc 3.1.1，并在本机 MySQL 8.4.6 中验证了构建、启动及 Flyway V1 至 V5 迁移。认证、JWT 验签、Redis 验证码、OpenAPI 生成和在线会话管理已有自动测试或本机验证；MyBatis-Plus 分页与完整浏览器链路仍待实测。第一版保持 MySQL 8.4 LTS、Redis 的模块化单体部署。

## 第一版必需

| 能力 | 推荐依赖或实现 | 放置位置 | 用途 |
|---|---|---|---|
| 语言与构建 | Java 21、Maven Wrapper、Spring Boot BOM | 父 POM | 统一编译与依赖版本 |
| HTTP API | Spring Web MVC、内嵌 Tomcat | 启动模块 / 系统模块 | REST 接口、JSON 响应 |
| 安全 | Spring Security、OAuth2 Resource Server JWT | 系统模块 | Bearer Token 校验、接口与方法授权 |
| 密码 | Spring Security `PasswordEncoder` | 系统模块 | 密码哈希与校验 |
| 数据访问 | MyBatis-Plus Spring Boot 4 starter | 系统及业务模块 | 标准 CRUD、条件查询 |
| 分页 | MyBatis-Plus 分页插件及其 JSQLParser 模块 | `admin-base-core` | MySQL 分页，统一转换为 `PageResult` |
| 数据库驱动 | MySQL Connector/J、Spring JDBC 事务 | 启动/数据访问模块 | 连接池、事务管理 |
| 数据库迁移 | Flyway Core、Flyway MySQL 模块 | 启动模块 | 建表、默认角色与菜单版本化 |
| 缓存 | Spring Data Redis（默认 Lettuce） | 启动/系统模块 | 登录验证码及限流；第一版不缓存权限决策 |
| 参数校验 | Spring Validation / Jakarta Bean Validation | 系统业务 DTO 与服务入口 | 请求字段与服务参数校验 |
| 接口文档 | springdoc-openapi 3.x Web MVC starter、Apifox | 启动模块 / 团队平台 | 后端生成 OpenAPI，Apifox 导入并协作 |
| 可观测性 | Spring Boot Actuator、Micrometer、Logback | 启动模块 | 健康检查、基础指标、结构化日志 |
| 测试 | Spring Boot Test、JUnit、AssertJ、Mockito | 各模块测试范围 | 用例与接口验证 |
| 数据库集成测试 | Testcontainers MySQL | 测试范围 | 验证迁移、Mapper 和权限 SQL |

Spring Boot 4 中 Web MVC 优先使用 `spring-boot-starter-webmvc`。MyBatis-Plus 应选择对应的 **Spring Boot 4 starter**，不要再叠加普通 MyBatis starter。MyBatis-Plus 3.5.9 起分页插件需要额外的 JSQLParser 依赖。Flyway 对 MySQL 需要其数据库支持模块。springdoc 使用与 Spring Boot 4 对应的 3.x 系列。这些组合在创建 `pom.xml` 时以官方兼容说明和实际构建结果为准。

## 已有设计中需要补充的点

1. **认证实现**：短期签名 JWT 作为 Access Token；长期随机 Refresh Token 存 HttpOnly Cookie，服务端仅保存摘要并轮换。JWT 验签交给 Spring Security Resource Server；第一版权限决策查询 MySQL 当前数据，不只信任旧 JWT 中的角色。
   登录图片验证码使用 Redis 保存短时挑战，验证后原子消费；验证码不新增 MySQL 表，也不能替代按账号和 IP 分别执行的限流。
2. **参数校验**：统一启用 Bean Validation；分页范围、用户名、菜单路径和权限码都在请求入口校验。
3. **运行监控**：提供仅限内部访问的健康检查和必要指标；日志带请求 ID，禁止输出密码、令牌与敏感请求体。
4. **集成测试**：优先用真实 MySQL 容器验证 Flyway、MyBatis-Plus 映射、角色授权与数据权限 SQL；H2 不能代替 MySQL 方言验证。
5. **版本管理**：使用 Maven Wrapper 与父 POM 统一锁版本；不在各模块重复写不同版本。

## 架构评审结论

- **保留** Java 21、Spring Boot 4.1.x、Spring Security、MyBatis-Plus、Flyway、Redis、OpenAPI 和 Testcontainers 的组合。这些组件各有明确职责，不需增加微服务基础设施。
- **数据库改为 MySQL 8.4 LTS**。MySQL 8.0 已在 2026 年 4 月结束生命周期，新项目应以 8.4 LTS 开始；现有迁移语法以 8.4 环境实际执行验证。
- **Redis 不作为权限真相来源**。用户、角色、授权和刷新会话的权威状态在 MySQL；第一版每次受保护请求查询 MySQL 的会话与有效授权，不引入权限缓存。Redis 仅存验证码和限流状态；登录防护依赖 Redis 时故障必须拒绝登录，不能绕过验证码或限流。
- **控制复杂度**。API 模块先作为空模块保留，出现真实跨模块契约时再加入类型；不要为每个内部帮助类创建接口，也不要预装代码生成器、工作流、消息队列或搜索引擎。
- **安全边界由后端承担**。菜单和按钮的显示不是授权；所有业务 API 校验权限码，列表和单条记录操作均校验数据范围。JWT 保持短有效期，重要撤销场景检查服务端会话状态。
- **先做兼容性验证**。工程落地的第一步运行最小启动、Flyway 迁移、MyBatis-Plus 分页、自定义 Mapper、JWT 验签和 OpenAPI 生成的集成测试；通过后锁定依赖版本。
- **区分迁移和运行凭据**。本地开发允许启动时自动迁移；生产应由受控部署步骤使用可改表的迁移凭据执行 Flyway，应用日常连接不长期持有 DDL 权限。
- **固定时间语义**。MySQL `DATETIME` 不保存时区；应用与数据库会话统一使用北京时间（`Asia/Shanghai`/`+08:00`），尤其要验证 SQL 默认值 `CURRENT_TIMESTAMP` 与应用写入值一致。

## 按业务需要增加

| 场景 | 可选能力 | 增加条件 |
|---|---|---|
| 头像、附件 | 对象存储适配器（S3/MinIO/云厂商） | 确定文件管理需求与部署环境后 |
| Excel 导入导出 | 专用 Excel 库与异步导出 | 有真实批量业务时 |
| 定时任务 | Spring Scheduling；复杂任务再选 Quartz | 有明确任务、失败重试与管理需求时 |
| 多系统 SSO | OIDC/OAuth2 Client 或外部身份提供方 | 需要接入现有企业身份系统时 |
| 消息队列 | RabbitMQ/Kafka 等 | 出现跨系统异步解耦需求时 |
| 搜索 | Elasticsearch/OpenSearch | MySQL 检索能力不足且有可量化需求时 |
| 对象映射 | MapStruct | DTO 转换重复且手写成本明显时 |
| 架构约束 | ArchUnit 或 Spring Modulith 验证 | 工程模块落地时加入测试，防止循环依赖 |
| 本地接口文档 UI | Knife4j | 仅在 Spring Boot 4 兼容性验证通过后加入；不作为 Apifox 的替代 |

第一版不默认加入微服务组件、分布式事务、工作流、代码生成器、消息队列和搜索引擎。保持模板可运行、可理解、可移植，后续按真实项目需要扩展。
