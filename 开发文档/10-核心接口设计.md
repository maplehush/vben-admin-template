# Vben 登录与权限核心接口设计（第一版）

本设计覆盖 Vben Admin 5 的图片验证码、登录闭环及权限接口，最初基于上游提交 [`c5204a6`](https://github.com/vbenjs/vue-vben-admin/commit/c5204a69b8374682c59cb35e7a43d474cf125a82)的 `apps/web-antd` 核对。当前模板使用 `apps/web-antdv-next`。后端已实现第 1–7 节接口、`PUT /user/password` 及系统管理接口；动态菜单包含已经打包的系统管理页面。[可导入 Apifox 的唯一 OpenAPI 文件](openapi/核心接口.openapi.json)同时包含登录闭环和系统管理接口；权限管理字段详见[详细设计](12-权限管理接口详细设计.md)。

## 接入与通用规则

- 浏览器请求前缀为 `/api`，例如 `/api/auth/login`。后端 Controller 的逻辑路径为 `/auth/login`；Nginx/Vite 代理负责前缀处理，不能让前端同时适配两套路由。
- 第一版采用**同源部署**：前端和 `/api` 在同一站点，通过代理转发到 Spring Boot。这样登录响应能可靠设置 Refresh Token Cookie。若改为跨域部署，需同步修改前端登录请求的 `withCredentials`、后端 CORS 与 Cookie 策略。
- 除刷新接口成功响应外，统一返回 `application/json`：`{ "code": 0, "data": ..., "message": "ok" }`。业务失败时 `code` 非零、`data` 为 `null`、`message` 可读；同时使用对应 HTTP 状态码。
- 需要登录的接口使用 `Authorization: Bearer <accessToken>`。响应附带 `X-Request-Id`，认证相关响应设置 `Cache-Control: no-store`。
- 用户、菜单和权限结果不包含密码哈希、Refresh Token 或内部数据库实体。
- 模板不开放公开注册、手机号、扫码或第三方登录；账号由初始化命令或后台用户管理创建。登录页不展示 Vben 演示账号选择器，不预填密码，也不保留滑块。标题、副标题、账号、密码、图片验证码、记住账号和登录按钮保留；用户只输入账号、密码、验证码三项，“记住账号”是可选勾选项。验证码输入框与图片同行等高，点击图片可刷新；页面不展示“看不清”和“忘记密码”文字。

## 1. `GET /auth/captcha`

**认证：**匿名。**限流：**按 IP 限制验证码签发频率。成功 `200`：

```json
{
  "code": 0,
  "data": {
    "captchaId": "d23d660c-65ba-40af-91ee-4dd930814776",
    "imageData": "data:image/png;base64,...",
    "expiresInSeconds": 120
  },
  "message": "ok"
}
```

服务端生成一次性随机 `captchaId` 和 5 位、不易混淆的验证码字符；仅将图片发给浏览器，答案存 Redis，120 秒后过期。图片和响应均禁止缓存，答案不得进入日志、响应或 MySQL。验证码获取接口本身也要限流；Redis 不可用时不签发可绕过的验证码。

## 2. `POST /auth/login`

**认证：**不需要 Bearer Token。**限流：**按用户名、按 IP 分别限制尝试次数，不能只用“IP + 用户名”组合计数；用户名不存在与密码错误返回相同提示。

请求：

```json
{
  "username": "admin",
  "password": "用户输入的密码",
  "captchaId": "d23d660c-65ba-40af-91ee-4dd930814776",
  "captchaCode": "A7K2M"
}
```

成功 `200`：

```json
{ "code": 0, "data": { "accessToken": "eyJ..." }, "message": "ok" }
```

同时设置 `refresh_token` Cookie。Cookie 为 `HttpOnly`、`Secure`（生产环境）、`SameSite=Lax`，Path 与公开的 `/api/auth` 前缀匹配；不要把 Refresh Token 放进 JSON。建议默认 Access Token 有效期 15 分钟、Refresh Token 7 天，均可配置。用户停用、密码错误或达到限流阈值分别返回 403、401 或 429，且不泄露用户是否存在。

服务端校验验证码时忽略英文字母大小写，并**原子消费** `captchaId`，成功或失败都不得复用；错误、过期或缺失时返回 `40001`，前端获取新图片。账号密码错误也应刷新验证码。页面只有账号、密码、验证码**三个输入项**；登录请求除这三项外，程序自动附带不可见的 `captchaId`，用于对应当前图片，也避免多个标签页的挑战相互覆盖。现有 `SliderCaptcha` 只给出前端布尔值，正式页面须完全移除；`selectAccount`、`rememberMe` 不进入登录请求。验证码不用于 `/auth/refresh`。第一版默认每次账号密码登录均验证图片验证码；验证码与限流、登录日志共同构成防护。

## 3. `POST /auth/refresh`

**认证：**使用 `refresh_token` Cookie，不要求有效 Access Token。请求体为空。服务端验证会话有效性、用户状态，并以事务或原子操作轮换 Refresh Token；旧令牌立即失效。校验 Cookie 请求的 `Origin` 与允许来源。

前端对同一页面的并发 401 使用单次刷新请求，其余请求等待同一结果；服务端在事务中锁定会话行，比较当前令牌摘要后再轮换。两个请求携带同一旧令牌时只有一个能成功，另一个返回 401；不能让后到请求覆盖已经轮换的新摘要。刷新失败时清除本地登录态并返回登录页。

成功 `200` 的响应体是 **`text/plain` 原始 Access Token 字符串**，例如 `eyJ...`，同时设置新的 Cookie。这是为当前 Vben 的 `baseRequestClient` 和 `resp.data` 读取方式保留的兼容契约；普通的 `{code,data}` 包装不能直接用于此接口。缺少、失效或已撤销的 Refresh Token 返回 `401` JSON 错误，并清除 Cookie。

## 4. `POST /auth/logout`

**认证：**使用 `refresh_token` Cookie；请求体为空。找到会话时撤销，随后清除 Cookie。没有 Cookie 或会话已撤销时仍返回成功，便于前端幂等退出。成功 `200`：

```json
{ "code": 0, "data": "", "message": "ok" }
```

Cookie 端点同样校验允许的 `Origin`。Access Token 带会话 ID；需要即时退出时，受保护请求检查该会话是否已撤销，不能只等 JWT 自然过期。

## 5. `GET /user/info`

**认证：**Bearer Token。成功 `200`：

```json
{
  "code": 0,
  "data": {
    "userId": "1",
    "username": "admin",
    "realName": "系统管理员",
    "avatar": "",
    "roles": ["super_admin"],
    "homePath": "/dashboard/workspace",
    "desc": "",
    "mustChangePassword": false
  },
  "message": "ok"
}
```

`userId` 必须是字符串，避免 JavaScript 大整数精度问题。`roles` 返回当前有效角色的编码，不返回角色 ID；`homePath` 应指向用户可访问的路由，若原首页被撤权则回退到可用首页。登录成功后先请求本接口；`mustChangePassword=true` 时跳到固定的、要求已登录的改密路由，改密前**不请求** `/auth/codes` 或 `/menu/all`，后端仅允许访问本人信息、本人改密、刷新及退出接口，不能只靠前端跳转限制。改密成功后按密码修改规则重新登录。Vben 当前 `authLogin` 并行请求用户信息和权限码，正式接入时必须调整调用顺序；`BasicUserInfo` 使用 `userId`、`username`、`realName`、`avatar`、`roles`，当前 `UserInfo` 还含 `homePath` 与 `desc`，需扩展 `mustChangePassword` 字段。上游类型中存在未被 Mock 使用的 `token` 字段，后端不重复返回 Access Token，前端正式接入时修正该类型。

## 6. `GET /auth/codes`

**认证：**Bearer Token。成功 `200`：

```json
{ "code": 0, "data": ["system:user:list", "system:user:create"], "message": "ok" }
```

权限码来自有效角色授权的 `BUTTON`/`API` 资源，去重后按字典序返回；无操作权限返回空数组。`super_admin` 在服务端拥有全部权限，接口也应返回当前有效资源的权限码，以便前端按钮显示正常。菜单和按钮展示不替代后端接口权限校验。

## 7. `GET /menu/all`

**认证：**Bearer Token。成功 `200`：

```json
{
  "code": 0,
  "data": [
    {
      "name": "System",
      "path": "/system",
      "redirect": "/system/user",
      "meta": { "title": "system.title", "icon": "carbon:settings", "order": 100 },
      "children": [
        {
          "name": "SystemUser",
          "path": "/system/user",
          "component": "/system/user/list",
          "meta": { "title": "system.user.title", "icon": "carbon:user" }
        }
      ]
    }
  ],
  "message": "ok"
}
```

只返回启用且获授权的 `CATALOG`/`MENU`/`EMBEDDED`/`LINK`，必要的目录或页面父节点可补齐；`BUTTON`/`API` 不进入路由树。`name` 全局唯一，普通页面的 `component` 必须映射到前端已打包页面；内嵌与外链使用 Vben 的 `IFrameView`，分别在 `meta.iframeSrc` 与 `meta.link` 返回 HTTP/HTTPS 地址。`meta.title` 可使用 Vben 国际化 key；同级按 `sort_order` 排序。无菜单返回 `[]`，前端应有无权限落点。前端启用 `accessMode: 'backend'`。

## 错误与安全规则

| HTTP | `code` | 场景 |
|---|---:|---|
| 400 | 40000 | 参数格式错误 |
| 400 | 40001 | 验证码错误、缺失、已使用或过期 |
| 401 | 40100 | 缺少、过期或无效的 Access Token |
| 401 | 40101 | 登录凭据错误 |
| 401 | 40102 | Refresh Token 缺少、过期、重放或会话撤销 |
| 403 | 40300 | 用户停用或无权访问 |
| 429 | 42900 | 登录频率超限 |
| 500 | 50000 | 未预期服务端错误；响应不暴露内部细节 |

401 的受保护请求可触发前端刷新并重试**一次**；`/auth/login`、`/auth/refresh` 不应进入刷新循环。Vben 的 `enableRefreshToken` 默认关闭，正式接入时须在 `web-antdv-next` 启用。Access Token 建议包含 `sub`（用户 ID）、`sid`（会话 ID）、`iat`、`exp`、`iss`；服务端验签后，每次受保护请求查询 MySQL 的会话、用户状态与当前有效授权。第一版不缓存权限决策，也不把 JWT 内角色声明当作授权依据。刷新令牌使用高熵随机值，数据库仅存摘要。

## 验收场景

1. 验证码获取限流、120 秒过期、单次消费；不填写验证码或绕过前端直接请求登录都被服务端拒绝。
2. 正确/错误密码、停用用户、按账号及 IP 分别限流；验证码或密码错误后可刷新图片重试。
3. 登录后 `/user/info`、`/auth/codes`、`/menu/all` 与用户角色一致；首次改密用户不请求后两者，改密前不能访问业务接口。
4. Access Token 过期后刷新并重试一次；Refresh Token 轮换后旧令牌不能重用。
5. 退出后 Cookie 清除，会话失效；重复退出仍成功。
6. 角色授权变化后，菜单、权限码和后端 API 授权保持一致。
7. 无权限用户不能通过直接请求业务接口绕过按钮隐藏。
8. 正式登录页无演示账号、预填密码、注册或其他未实现的登录入口；“记住账号”只在成功后保存用户名，验证码输入框和图片同行等高。
