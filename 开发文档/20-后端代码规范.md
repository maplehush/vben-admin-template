# 后端代码规范

本规范用于 `backend/`，以当前代码和 `backend/AGENTS.md` 为准。参考 JeecgBoot 的模块划分和易读的中文注释，具体规则由本项目统一执行。

## 模块与包

- 依赖方向为 `admin-system-start → admin-system-biz → admin-system-api → admin-base-core`。`admin-system-api` 已创建，当前没有 Java 类型；只在产生真实跨模块调用时放入稳定契约。
- `admin-system-biz` 先按功能分 `auth/user/role/dept/menu/permission/dict/audit/file`，再在功能内按职责分 `controller/service/impl/mapper/entity/dto/vo/config/constant`。公共 HTTP 适配放 `common/web`。
- Controller 只适配 HTTP；Service 负责权限、校验、事务与业务规则；Mapper 负责持久化。单表查询、计数和排序优先使用 MyBatis-Plus 的 `LambdaQueryWrapper`；联表、复杂筛选、行锁和原子更新放 Mapper XML。尚未配置分页拦截器时，保留现有绑定参数的分页 SQL，不用 `last` 拼接分页参数。Service 不嵌入 SQL。
- `service/ISysXxxService` 与 `service/impl/SysXxxServiceImpl` 成对命名。对外业务服务使用接口；内部无跨层调用的帮助类不为形式增加接口。查询职责较多时独立 `ISysXxxQueryService`。
- 单表查询（包括树查询和 `FOR UPDATE`）直接映射对应实体；只加载部分字段时，在 Mapper 注释写明字段范围。联表列表可直接映射稳定的响应 VO，数据库主键与状态值由 VO 构造器转换；鉴权等内部查询确需跨表状态时才定义独立结果类型，不为每条 SQL 创建一个 `Row` 包装类。加锁查询必须留在原业务事务内。

## 命名和模型

| 职责 | 示例 | 规则 |
| --- | --- | --- |
| 表实体 | `SysUser`、`SysRole`、`SysDept` | 系统表统一 `Sys` 前缀；部门写 `Dept` |
| 关联实体 | `SysUserRole` | 按对应表和业务关系命名 |
| Controller | `SysUserController` | 按资源命名，不加 `Management`、`Query` 页面后缀 |
| Mapper | `SysUserMapper`、`SysUserQueryMapper` | 与实体或具体查询职责对应 |
| 请求条件 | `UserQueryDTO` | Controller 到查询服务使用 DTO，不传原始 HTTP 参数组合 |
| 写入请求 | `CreateUserDTO`、`UpdateUserDTO` | 功能包下的 `dto`，只包含请求字段与入口校验 |
| 响应 | `UserSummaryVO`、`UserDetailVO` | 功能包下的 `vo`，列表、详情和特殊视图按用途区分 |
| 分页响应 | `PageResult<UserSummaryVO>` | 统一使用 `admin-base-core` 的 `PageResult` |

实体映射数据库表，不直接作为 HTTP 响应；联表查询投影与响应模型按需要分开。公共 `ApiResult`、`PageResult` 放 `admin-base-core/common/api/vo`。只有真实跨模块复用的传输模型才放入 `admin-base-core/common/api/dto`；系统管理的 HTTP DTO/VO 留在功能包。新增和其他写操作统一返回 `ApiResult<Boolean>`。内部 Service 命令模型可以留在服务接口附近，但 HTTP DTO/VO 不定义为 Controller 内部 record。

实体到 VO 的 ID、状态、时间和树形子节点需要明确转换；只有字段名称、类型和含义一致时才使用属性拷贝。不要为了省几行构造代码而把实体直接返回给前端。

## 错误与审计

- 系统模块的 `ApiErrorCode` 集中定义 HTTP 状态、业务错误码和对外文案。业务代码抛 `ApiException`，`GlobalExceptionHandler` 统一转为 `ApiResult(code, null, message)`；保留既有错误码、文案和状态，避免在 Controller 中自行拼接失败响应。
- 管理写入操作在原业务事务内显式调用 `IOperationAuditService.record`。审计服务统一采集请求 ID、来源 IP，`OperationAuditMapper.xml` 统一写 `sys_operation_log`；失败的业务写入和审计写入一同回滚。`AuditTargetType` 限定目标资源类型。

## 字段、注释与时间

- 持久化实体的每个字段写简短中文业务注释。例如“父部门 ID，为空表示根部门”“状态：1 启用，0 禁用”；“部门名称”这样的短语不加句末句号。类、接口及复杂规则补充职责或约束注释，不写作者日期模板和重复类型信息。
- 实体用 Lombok `@Getter`、`@Setter` 消除机械访问方法；除确有必要外不用 `@Data`。`@TableName`、`@TableId` 明确表名和主键策略；不入库的实体字段要标 `@TableField(exist = false)`，接口展示字段优先放 VO。
- 共享状态常量放 `admin-base-core/common/constant`，功能专属常量放对应功能的 `constant`；仅收纳稳定且复用的规则。可配置业务选项使用字典表。
- 数据库 `DATETIME` 按北京时间和秒精度存储；响应使用 `LocalDateTime`，由启动模块全局 Jackson 配置按 `DateUtils.DATE_TIME_PATTERN` 输出 `yyyy-MM-dd HH:mm:ss`，特殊字段才使用 `@JsonFormat`。业务时间由注入的 `Clock` 提供，JWT 等绝对时间继续用 `Instant`。

## 格式化和验证

- IDE 启用 `backend/.editorconfig`：UTF-8、LF、末尾换行；Java 和 XML 为 4 空格，YAML 为 2 空格。
- Java 的最终格式由根 POM 的 Spotless 固定：Palantir Java Format、import 排序、删除未使用 import。IDE 的 Java 格式化规则应与 Maven 输出一致，避免个人配置反复改写文件。
- 格式化执行 `./mvnw spotless:apply`；验证执行 `./mvnw clean test`。Maven `test` 生命周期包含 `spotless:check`，格式不一致会使构建失败。
- 管理接口的路径清单统一在 `RouteSecurityPolicy`，对应测试核对 Controller 路由覆盖；新增接口同时维护后端权限检查和 OpenAPI 契约。涉及 MySQL 方言、事务或约束时补充隔离 MySQL 集成验证。
