# 项目结构

当前项目以根目录作为唯一 Git 仓库，由 `frontend/`、`backend/` 和 `开发文档/` 组成；设计素材位于 `开发文档/design/`。后端是 Java 21 + Spring Boot 4 的模块化单体，Maven 依赖方向为 `admin-system-start → admin-system-biz → admin-system-api → admin-base-core`；只部署 `admin-system-start` 产生的一个 JAR。

| 模块 | 职责 |
| --- | --- |
| `backend/admin-base-core` | 跨模块的响应、分页、日期时间工具和固定启禁用状态 |
| `backend/admin-module-system` | 系统模块的 Maven 聚合目录，不放业务 Java 代码 |
| `backend/admin-module-system/admin-system-api` | 预留的跨模块契约模块，当前没有 Java 类型 |
| `backend/admin-module-system/admin-system-biz` | 认证、用户、角色、部门、菜单、接口权限、字典、审计和文件上传 |
| `backend/admin-module-system/admin-system-start` | 启动类、统一时钟、运行配置、Flyway 资源装配与集成测试 |
| `backend/schema` | Flyway 迁移唯一维护源 |

系统业务包先按功能划分，再按 `controller/service/impl/mapper/entity/dto/vo/config/constant` 划分；只创建有真实职责的包。查询服务以 DTO 接收条件，以 VO 返回结果；分页使用公共 `PageResult<VO>`。具体目录见[详细项目目录结构](07-详细项目目录结构.md)。API 模块按项目约定预先建好，真实跨模块调用出现后才向其中放稳定契约。正式业务 Controller 不写持久化和业务规则，Service 不直接执行 SQL。
